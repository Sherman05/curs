# Информационно-аналитическая система мониторинга успеваемости студентов с AI-модулем

Веб-приложение для мониторинга успеваемости студентов вуза с интегрированным
модулем генерации учебных материалов на основе большой языковой модели (Claude).
Объединяет аналитику успеваемости, AI-генерацию тестов и материалов и адаптивное
обучение для студентов из группы риска.

## Стек технологий

| Слой | Технологии |
|------|-----------|
| Backend | Flask 3, SQLAlchemy 2, Flask-Login, Flask-Migrate, Flask-WTF |
| База данных | SQLite |
| Frontend | Jinja2, Bootstrap 5, Chart.js |
| AI | Anthropic Claude (`claude-sonnet-4-5`) |
| Отчёты | openpyxl (Excel) |
| Безопасность | Werkzeug (хеш паролей), CSRF (Flask-WTF) |
| Демо-данные | Faker |

## Установка и запуск

```bash
# 1. Клонировать репозиторий
git clone <repo-url> && cd curs

# 2. Виртуальное окружение
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate

# 3. Зависимости
pip install -r requirements.txt

# 4. Настройки окружения
cp .env.example .env
# В .env пропишите:
#   SECRET_KEY=<случайная строка>
#   ANTHROPIC_API_KEY=<ваш ключ>     # без ключа AI работает в demo-режиме
#   AI_MODEL=claude-sonnet-4-5

# 5. Создать БД и загрузить тестовые данные
flask --app app seed

# 6. Запуск
flask --app app run --debug
```

Приложение: http://127.0.0.1:5000

> **Demo-режим AI.** Если `ANTHROPIC_API_KEY` не задан, AI-модуль возвращает
> корректные по структуре заглушки — приложение полностью функционально без ключа.

## Демо-аккаунты

После `flask --app app seed` (пароль у всех — `password`):

| Роль | Логин | Назначение в демо |
|------|-------|-------------------|
| Администратор | `admin` | общая статистика, общий отчёт |
| Преподаватель | `teacher1` … `teacher5` | оценки, генерация тестов, экспорт групп |
| Студент (слабый) | `student1` | средний < 3.5 по 7 предметам — демо адаптивки |
| Студент (с результатом) | `student7` | имеет пройденный демо-тест |
| Студенты | `student2` … `student30` | прочие |

В БД заранее создан **готовый демонстрационный тест** «Основы баз данных»
(предмет «Базы данных», преподаватель `teacher1`), **одно прохождение**
(`student7`, 3/4) и **одни доп. задачи** (`student1`) — чтобы демонстрация
не зависела от доступа к AI.

## Реализованные модули

### Модуль 1 — Аналитика и мониторинг успеваемости
- Три роли (студент / преподаватель / администратор) с разграничением доступа
- Регистрация студентов с выбором группы; вход/выход
- CRUD оценок для преподавателя (только по своим предметам)
- Просмотр всех оценок администратором с пагинацией
- Дашборды для каждой роли: средний балл, распределение оценок (Chart.js),
  топ студентов, группа риска (средний < 3.5)
- Аналитика: средние по студенту/группе/предмету, обзоры для преподавателя
- Экспорт отчётов в Excel: успеваемость группы, общий отчёт (4 листа),
  зачётная книжка студента — с цветовой дифференциацией средних

### Модуль 2 — AI-генерация учебных материалов
- Мастер генерации теста: преподаватель выбирает предмет → тему → число вопросов
- Генерация теста моделью `claude-sonnet-4-5` по строгой JSON-схеме
- Редактируемая форма результата: преподаватель правит и сохраняет
- Прохождение теста студентом онлайн с автопроверкой и разбором ответов
- Журнал обращений к LLM (`ai_generation_logs`): запрос, ответ, токены
- Надёжность: валидация структуры, одна повторная попытка при сбое парсинга,
  понятные сообщения об ошибке, demo-режим без ключа

### Модуль 3 — Адаптивное обучение
- Триггер: средний балл студента по предмету < 3.5
- На дашборде студента — кнопка «Получить доп. задачи» по слабым предметам
- Генерация персональных практических задач (`generate_remedial_tasks`)
- Серверная валидация: предмет существует, студент его изучает, средний < 3.5
- Сохранение и просмотр доп. задач в личном кабинете

## Ограничения текущей реализации

Сознательно вынесено за рамки в условиях ограниченного времени:
- **PDF-экспорт** не реализован (есть только Excel)
- **Импорт оценок из CSV** не реализован
- **Учёт посещаемости** (таблица `attendance`) заполняется в seed, но UI нет
- **Слабые темы внутри предмета** не выделяются (в `grades` нет колонки темы),
  поэтому доп. задачи генерируются по предмету в целом

## Сценарий демонстрации

1. **Администратор** (`admin`): дашборд — карточки (30 студентов, 5 преподавателей,
   средний 3.95, 5 в группе риска), график распределения, топ-10, группа риска.
2. Администратор → «Скачать общий отчёт» → Excel с 4 листами.
3. **Преподаватель** (`teacher1`): дашборд — предметы, график по группам, группа риска.
4. Преподаватель → «Оценки» → выбрать предмет → добавить оценку студенту.
5. Преподаватель → «Материалы» → «Сгенерировать тест» → предмет, тема, 5 вопросов
   → правка → сохранение.
6. Преподаватель → открыть демо-тест «Основы баз данных» → видно прохождение `student7` (3/4).
7. Преподаватель → дашборд → «Экспорт Excel» по группе → Excel с цветными средними.
8. **Студент** (`student1`): дашборд — средний < 3.5, блок «Слабые предметы».
9. Студент → «Тесты» → пройти демо-тест «Основы баз данных» → результат с разбором.
10. Студент → дашборд → по слабому предмету «Получить доп. задачи» → 5 задач.
11. Студент → открыть готовые доп. задачи (созданы в seed).
12. Студент → «Скачать зачётку» → Excel с оценками и средними.
